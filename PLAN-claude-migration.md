## Step 1 — CLI contract and decisions (medium)
- [x] Local CLI facts recorded from `claude --help` (v2.1.330): flags above exist; `--effort` choices `low, medium, high, xhigh, max`;
      `--permission-mode` choices `acceptEdits, auto, bypassPermissions, manual, dontAsk, plan`; `--permission-prompts host|none`;
      `--restricted`; `--tools`; `--no-session-persistence`; `--max-budget-usd`.
- [x] Read the remaining docs pages (sandboxing, settings, env vars, permission modes, permissions). Findings:
  - `-p` with no mode starts in Manual (`default`): anything needing approval is **denied** (no prompt).
  - `default`: reads inside working dirs + read-only Bash only. `plan`: edits blocked, read-only Bash runs (plain answer in `-p` unconfirmed).
  - `acceptEdits`: edits and `mkdir/touch/rm/rmdir/mv/cp/sed` auto-approved **only inside cwd / additionalDirectories**; other Bash denied in `-p`.
  - `dontAsk`: denies everything that would prompt; runs only no-approval actions + `--allowedTools` / `permissions.allow`.
  - `bypassPermissions` = `--dangerously-skip-permissions`: everything runs; deny rules still apply; refused as root (bot user is non-root).
  - Bash sandbox: off by default; per run via `--settings '{"sandbox":{"enabled":true,...}}'`. Keys: `autoAllowBashIfSandboxed`,
    `allowUnsandboxedCommands` (set `false`), `failIfUnavailable` (set `true`), `filesystem.allowWrite/denyWrite/allowRead/denyRead`,
    `network.allowedDomains` (starts empty → no network). Writable: cwd, temp dir, added dirs. Reads are NOT confined
    (`~/.ssh` readable) → `permissions.blockReadsOutsideWorkingDirectories: true` if needed.
  - Sandbox on Linux needs `bubblewrap` + `socat` (`sudo apt-get install bubblewrap socat`); Ubuntu may need an AppArmor profile for `bwrap`.
  - Env overrides: `ANTHROPIC_API_KEY` is **always** used in `-p` when present (bills API, beats subscription);
    `CLAUDE_CODE_EFFORT_LEVEL` beats `--effort`; `--model` beats `ANTHROPIC_MODEL`; `CLAUDE_CONFIG_DIR` moves settings + sessions;
    `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` hides credentials from Bash subprocesses; `DISABLE_AUTOUPDATER=1` stops auto-updates;
    `BASH_DEFAULT_TIMEOUT_MS` 2 min / `BASH_MAX_TIMEOUT_MS` 10 min; `-p` waits for background work up to 10 min
    (`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`).
  - Session transcripts are removed after `cleanupPeriodDays` (default 30, per the sessions page; settings reference not fully read).
- [x] **Ask user first:** permission for sample runs — allowed. 3 runs locally (Windows, v2.1.330, `haiku`, `--effort low`,
      `--permission-mode default`) in an empty temp dir; their local data removed afterwards with `claude purge <dir> --yes`.
- [x] Verified stream-json contract:
  - Prompt **only on stdin** (no positional prompt) works with `-p`.
  - `--session-id <uuid>` creates the session with exactly that id; `--resume <id>` continues it (same `session_id` everywhere).
  - Every line is JSON with `type`. Seen: `system/init` (`session_id`, `model`, `permissionMode`, `cwd`, `apiKeySource`,
    `claude_code_version`), `assistant` (`message.content[]`: `{type:"text",text}` / `{type:"tool_use",name,input}`),
    `user` (`tool_result` blocks, `is_error`), `rate_limit_event`, `system/task_summary` (`detail` — short human phase text),
    `system/post_turn_summary`, `result`.
  - **`result` is not always the last line** (a `system/task_summary` came after it) → read until EOF, use the `result` event.
  - Success `result`: `subtype:"success"`, `is_error:false`, `result` (final text), `session_id`, `num_turns`,
    `total_cost_usd`, `duration_ms`, `permission_denials[]`, `terminal_reason`, `stop_reason`, `api_error_status`.
  - Error (wrong `--resume` id): exit code 1, single line `result` with `subtype:"error_during_execution"`, `is_error:true`,
    `errors:["No conversation found with session ID: <id>"]`, same text on stderr.
  - Transcript dir: `<config>/projects/<cwd with ':', '\', '/', '.' etc. replaced by '->/` (e.g. `C--Users-densu-...`).
    `claude purge <cwd> --yes` deletes the whole project's transcripts (not a single session).
  - Read-only Bash command (`ls`) ran in `default` mode without a prompt (`permission_decision: accept, source: config`).

## Decisions log
_Non-obvious decisions and deviations, newest last._

- 2026-11-22: Codex removed from the server (bot directory, `~/.codex`); the global npm package remains until the user removes it with `sudo`.
- 2026-11-22: Claude Code installed locally only as a reference for CLI flags; the bot will run Claude Code on the server.
- D1: keep 3 access modes. `read-only` → `--permission-mode default` (reads + read-only Bash; the rest is denied in `-p`);
  `workspace` → `--permission-mode acceptEdits` + Bash sandbox via `--settings` (writes only in the workdir, no network);
  needs `bubblewrap` + `socat` on the server; `full-access` → `--permission-mode bypassPermissions`.
- D2: auth with `claude setup-token` (1-year token, Max subscription) → GitHub secret `CLAUDE_CODE_OAUTH_TOKEN` → `app.env`;
  `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1` so Claude's commands don't see it; `ANTHROPIC_API_KEY` must not be set for the bot.
- D3: `CLAUDE_*` env vars, `Claude*` classes.
- D4: model aliases (`default`, `opus`, `sonnet`, `haiku`, `fable`; narrowed by env) + one effort list
  (`default`, `low`, `medium`, `high`, `xhigh`, `max`) for all models; the JSON catalog is removed.
- Step 2: `CLAUDE_CONFIG_DIR` is not a bot property; the bot and the `claude` child read it from the process environment
  (same approach as `CODEX_HOME` before).
- Step 2: efforts are global (not per model), so changing the model no longer resets effort; `--effort` may be used with
  model `default`.
- Step 2: the `/reasoning` command, menu kind and button were renamed to `effort` early (needed by the settings API);
  remaining Codex wording in texts stays for Step 5. `CodexRunner` got a temporary `--permission-mode` flag only to compile.
- Step 3: `--permission-prompts none` in every mode, so a denied action is not retried in a loop.
- Step 3: workspace mode confines writes and network, not reads (same as Codex `workspace-write`); no
  `blockReadsOutsideWorkingDirectories`.
- Step 3: `permission_denials[].tool_name` is taken from the Agent SDK shape; the sample runs had no denials, so this field
  is unverified until the first real denial.
- Step 3: the event parser moved from Step 4 into Step 3 because the runner reads the `result` event from it.
  `ClaudeRunner.newSession` only forgets the id for now; Step 4 rewrites it.
- Step 4: two-phase `resetPending` dropped. The guarantee that matters (the next message starts a new session) holds
  as soon as the empty id is saved; deleting the transcript is cleanup only.
- Step 4: a confirmed session is always resumed, never blocked by the bot's own transcript check: the transcript
  layout (`projects/<encoded cwd>/<id>.jsonl`) was seen only on Windows, and a wrong check would lock the bot.
- Step 4: the bot does not pass `CLAUDE_CONFIG_DIR` to `claude` explicitly (setting it also moves `.claude.json`);
  the child simply inherits the bot's environment.
- Step 6: `app.env` now has mode 600 (it holds the Telegram and Claude tokens); before it was world-readable.
- Step 6: "delete old `CODEX_*` secrets" dropped from User actions — none exist in the repo; "commit and push" added,
  because the workflow builds from GitHub.
- Step 7: the `claude` child inherited `TELEGRAM_BOT_TOKEN` from the bot (as Codex did), so a command Claude runs could
  print it. User agreed: `TELEGRAM_BOT_TOKEN` added to `ClaudeRunner.UNSET_ENVIRONMENT` (README updated); package passes.
- Not verified until the first server run: `claude auth status` exit code with only `CLAUDE_CODE_OAUTH_TOKEN`,
  `permission_denials[].tool_name`, transcript layout on Linux, sandbox on the server's Ubuntu.
- Step 8: not touched on `/new` — `history.jsonl` (global prompt history; no session id in its entries), `plans/`,
  `paste-cache/` (keying not documented), `shell-snapshots/` (removed by Claude Code on clean exit). `claude purge`
  was not used: it also deletes the user's own interactive data for the same directory.
- D5: native installer (`~/.local/bin/claude`), `DISABLE_AUTOUPDATER=1`, manual `claude update`; deploy checks a minimum
  version from `scripts/claude-version.txt`.
